RELX.iO — PROJECT HANDOFF / BACKUP AMAN
========================================

TUJUAN BERKAS
Dokumen ini adalah ringkasan teknis proyek untuk membantu pengembang atau AI assistant lain melanjutkan pekerjaan. Ini BUKAN backup/restore data pengguna. Berkas ini tidak berisi database, riwayat pengguna, API key, password, keystore, token GitHub, model offline, atau file privat perangkat.

IDENTITAS BUILD
Nama produk: RELX.iO
Application ID: dev.andikune.robotasisten.io
Bahasa implementasi utama: Kotlin
UI: Jetpack Compose + Material 3
Arsitektur utama: satu aplikasi Android, service foreground untuk overlay, Accessibility Service untuk tindakan layar atas permintaan, repository/Room untuk data lokal, adapter AI per mode.
Minimum Android: API 26 (Android 8.0)
Compile/target SDK saat dokumen sumber ini ditulis: 34
Versi rilis sumber saat dokumen ini ditulis: 1.2.2 / versionCode 5
Sumber otoritatif proyek: repository GitHub andikune-ux/Robot-Asisten-iO, branch main. Periksa commit paling baru sebelum melakukan perubahan.

GAMBARAN FITUR DAN ALUR
1. Beranda memilih mode jawaban dan memeriksa izin sebelum memulai overlay.
2. OverlayService menampilkan bubble robot dan panel Compose di atas aplikasi lain. Ketuk bubble membuka/menutup menu; double tap meminta analisis; tekan lama membuka menu. Menu menyediakan analisis soal, jawab otomatis, OCR/teks layar, Riwayat, Pengaturan, sembunyikan bubble dengan kontrol pemulihan notifikasi, dan matikan service.
3. MyAccessibilityService menjalankan screenshot/OCR atau fallback ke teks node aksesibilitas atas tindakan pengguna. Isi otomatis mencoba mengisi field yang sedang fokus; bila tidak dapat, hasil disalin ke clipboard dan aplikasi melaporkan keadaan itu secara jujur.
4. QuestionDetector mengenali pola soal, opsi, isian, hitungan, dan esai. FallbackChain memilih cache/aturan/AI sesuai mode. Hasil gagal harus tampil sebagai status gagal, bukan jawaban tebakan.
5. Mode Library memakai RuleEngine dan basis aturan lokal.
6. Mode Offline menggunakan ModelDownloader untuk memperoleh model dan OfflineAi/MediaPipe untuk inferensi lokal. Model memerlukan unduhan dan kompatibilitas perangkat.
7. Mode Cloud memakai konfigurasi provider/model/endpoint HTTPS dan penyimpanan rahasia ApiKeyStore. Jangan pernah menaruh API key dalam source, log, atau berkas Backup Aman.
8. Room menyimpan cache, aturan, riwayat, statistik, dan antrean AI. SettingsRepository menyimpan pengaturan aplikasi.
9. CrashHandler menulis laporan exception fatal terakhir ke penyimpanan privat aplikasi. Saat aplikasi dibuka kembali, MainActivity menampilkan dialog untuk menyalin log dan kembali. Jika dialog ditutup, log masih dapat diakses dari Debug/Crash Report sampai pengguna menghapusnya.
10. Backup Aman mengekspor dokumen teks ini bersama versi, waktu, dan informasi runtime perangkat yang tidak rahasia. Android 10+ membuat .txt di Penyimpanan internal/Relx IO/Backup aman melalui MediaStore.Files scoped. Android 8–9 memakai Storage Access Framework dan grant folder terbatas. Fitur ini tidak mengekspor atau memulihkan data aplikasi.

PERIZINAN ANDROID
- SYSTEM_ALERT_WINDOW: menampilkan overlay setelah pengguna mengaktifkan izin khusus Android.
- FOREGROUND_SERVICE dan FOREGROUND_SERVICE_SPECIAL_USE: service overlay berjalan sebagai foreground service dan menampilkan notifikasi berkelanjutan.
- POST_NOTIFICATIONS: kontrol service dan status notifikasi pada Android yang mensyaratkan persetujuan.
- INTERNET dan ACCESS_NETWORK_STATE: mode cloud serta pemantauan koneksi.
- REQUEST_IGNORE_BATTERY_OPTIMIZATIONS: pilihan agar sistem tidak mudah menghentikan overlay.
- BIND_ACCESSIBILITY_SERVICE: Android mengikat service aksesibilitas; pengguna mengaktifkannya sendiri melalui Settings.
- VIBRATE: feedback getar; implementasi harus tetap fail-safe bila hardware/izin bermasalah.
- Backup Aman tidak meminta MANAGE_EXTERNAL_STORAGE atau READ/WRITE_EXTERNAL_STORAGE. Android 10+ menulis berkas milik aplikasi memakai MediaStore.Files dengan RELATIVE_PATH “Relx IO/Backup aman”; Android 8–9 menggunakan ACTION_OPEN_DOCUMENT_TREE dengan grant URI terbatas/persistable. Tidak ada akses diam-diam ke seluruh file.

PETUNJUK MELANJUTKAN PROYEK
- Sebelum mengedit, periksa git status, branch dan commit terkini; buat perubahan sekecil mungkin.
- Jangan menghapus/mengganti applicationId jika APK harus menjadi update terhadap aplikasi yang sudah terpasang.
- APK yang ditandatangani key berbeda tidak dapat memasang update di atas APK lama. Pertahankan secrets signing yang sudah dikonfigurasi; jangan membuat key pengganti.
- Jangan commit keystore, API keys, nilai secrets, data pengguna, atau file build.
- Jalankan ./gradlew testDebugUnitTest assembleDebug (workflow menguji test dan membuat artifact bertanda tangan stabil).
- Periksa laporan crash nyata sebelum menyimpulkan akar masalah. Laporan ada di dialog awal setelah force close atau halaman Crash Report.
- Untuk Backup Aman, gunakan MediaStore.Files pada Android 10+ untuk path “Relx IO/Backup aman” dan SAF dengan persistable URI grant sebagai fallback Android 8–9. Hindari izin storage luas.
- Dokumentasi ini menggambarkan arsitektur source saat dibangun. Verifikasi commit dan isi file sebelum menjadikannya spesifikasi final.

CATATAN PRIVASI
Laporan crash memuat stack trace, model perangkat, versi Android, versi aplikasi, waktu, dan nama thread. Jangan menambahkan isi layar, clipboard, API key, password, atau rahasia ke laporan. File Backup Aman berupa teks plain; pengguna sebaiknya membagikannya hanya kepada pihak yang dipercaya.
