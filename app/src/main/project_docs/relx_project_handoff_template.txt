RELX.iO — PROJECT HANDOFF / BACKUP AMAN
========================================

TUJUAN BERKAS
Dokumen ini adalah ringkasan teknis proyek untuk membantu pengembang atau AI assistant lain melanjutkan pekerjaan. Ini BUKAN backup/restore data pengguna. Berkas ini tidak berisi database, riwayat pengguna, API key, password, keystore, token GitHub, model offline, atau file privat perangkat.

IDENTITAS BUILD
Nama produk: RELX.iO
Application ID: dev.andikune.robotasisten.io
Bahasa implementasi utama: Kotlin
UI: Jetpack Compose + Material 3
Arsitektur utama: satu aplikasi Android, service foreground untuk overlay, Accessibility Service untuk tindakan layar atas permintaan, repository/Room untuk data lokal, adapter AI per mode.
Minimum Android: API 26 (Android 8.0)
Compile/target SDK saat dokumen sumber ini ditulis: 34
Versi build dokumen ini ditambahkan otomatis oleh Gradle dari konfigurasi aplikasi.
Sumber otoritatif proyek: repository GitHub andikune-ux/Robot-Asisten-iO, branch main. Periksa commit paling baru sebelum melakukan perubahan.

GAMBARAN FITUR DAN ALUR
1. Beranda memilih mode jawaban dan memeriksa izin sebelum memulai overlay.
2. OverlayService menampilkan bubble robot dan panel Compose di atas aplikasi lain. Ketuk bubble membuka/menyembunyikan panel tanpa menghapus hasil; double tap meminta analisa+jawab; tekan lama membuka menu. Panel diposisikan di sekitar bubble, berpindah sisi bila perlu, dan dibatasi terhadap tepi layar. Kartu soal/jawaban/OCR dapat discroll; tombol Tutup menutup hasil secara eksplisit dan menu dapat dibuka kembali dari bubble.
3. MyAccessibilityService menjalankan screenshot/OCR atau fallback ke teks node aksesibilitas atas tindakan pengguna. Isi otomatis hanya mengisi field yang sedang fokus dan tidak mengirim pesan. RELX Power membaca layar atas konfirmasi, memberi analisa/rencana AI, dan opsional menggulir sampai konten selesai atau berulang untuk teks sambungan lalu mencoba memulihkan posisi. RELX Power belum menekan tombol arbitrer, mengirim, Submit, menghapus, atau membayar; aksi eksternal memerlukan tinjauan dan persetujuan pengguna.
4. QuestionDetector mengenali pola soal, opsi, isian, hitungan, dan esai. FallbackChain memilih cache/aturan/AI sesuai mode. Hasil gagal harus tampil sebagai status gagal, bukan jawaban tebakan.
5. Mode Library memakai RuleEngine dan basis aturan lokal.
6. Mode Offline menyediakan Qwen2.5 0.5B, Qwen2.5 1.5B, dan TinyLlama 1.1B Chat dalam bundle MediaPipe `.task` yang diverifikasi ukuran/SHA-256. ModelDownloader memverifikasi ukuran dan SHA-256, mencoba melanjutkan file parsial memakai HTTP Range, dan menyediakan penghapusan model; OfflineAi memilih template prompt sesuai model. Kualitas, kecepatan, RAM, dan multilingual tetap bergantung pada model dan perangkat. Bundle `.litertlm` tidak boleh dimuat ke MediaPipe LlmInference.
7. Mode Cloud memakai konfigurasi provider/model/endpoint HTTPS dan penyimpanan rahasia ApiKeyStore. Jangan pernah menaruh API key dalam source, log, atau berkas Backup Aman.
8. Room menyimpan cache, aturan, riwayat, statistik, dan antrean AI. SettingsRepository menyimpan pengaturan aplikasi.
9. CrashHandler menulis laporan exception fatal terakhir ke penyimpanan privat aplikasi. Saat aplikasi dibuka kembali, MainActivity menampilkan dialog untuk menyalin log dan kembali. Jika dialog ditutup, log masih dapat diakses dari Debug/Crash Report sampai pengguna menghapusnya.
10. Backup Aman mengekspor dokumen teks ini, info runtime tidak rahasia, dan inventaris repository aktual. Inventaris dihasilkan otomatis pada setiap build oleh task Gradle dari struktur/file yang ada; file kunci, secrets, data privat, dan output build dikecualikan. Android 10+ mencoba membuat .txt di Penyimpanan internal/Relxio/Backup aman melalui MediaStore.Files scoped; jika perangkat membatasi folder root, aplikasi memakai SAF dan membuat subfolder Relxio/Backup aman di folder yang dipilih. Android 8–9 memakai SAF dengan grant terbatas. Fitur ini tidak mengekspor atau memulihkan data aplikasi.
11. RELX AI adalah halaman chat multi-turn untuk AI Offline atau AI API Key. Riwayat beberapa percakapan, persona, memory/knowledge, instruction, dan pilihan kedalaman disimpan lokal; pengguna dapat mengedit pesan lalu mengirim ulang atau meminta balasan ulang. Blok kode/template berpagar memiliki tombol salin per blok. Saat mode cloud dipakai, pesan, layar yang dikirim melalui RELX Power, dan memory yang dipilih dikirim ke provider API aktif; jangan masukkan rahasia.

PERIZINAN ANDROID
- SYSTEM_ALERT_WINDOW: menampilkan overlay setelah pengguna mengaktifkan izin khusus Android.
- FOREGROUND_SERVICE dan FOREGROUND_SERVICE_SPECIAL_USE: service overlay berjalan sebagai foreground service dan menampilkan notifikasi berkelanjutan.
- POST_NOTIFICATIONS: kontrol service dan status notifikasi pada Android yang mensyaratkan persetujuan.
- INTERNET dan ACCESS_NETWORK_STATE: mode cloud serta pemantauan koneksi.
- REQUEST_IGNORE_BATTERY_OPTIMIZATIONS: pilihan agar sistem tidak mudah menghentikan overlay.
- BIND_ACCESSIBILITY_SERVICE: Android mengikat service aksesibilitas; pengguna mengaktifkannya sendiri melalui Settings.
- VIBRATE: feedback getar; implementasi harus tetap fail-safe bila hardware/izin bermasalah.
- Backup Aman tidak meminta MANAGE_EXTERNAL_STORAGE atau READ/WRITE_EXTERNAL_STORAGE. Android 10+ mencoba MediaStore.Files dengan RELATIVE_PATH “Relxio/Backup aman”; bila perangkat membatasi folder root, aplikasi memakai ACTION_OPEN_DOCUMENT_TREE dengan grant URI baca/tulis terbatas dan persisten, lalu membuat subfolder Relxio/Backup aman di folder yang dipilih. Android 8–9 juga menggunakan ACTION_OPEN_DOCUMENT_TREE. Tidak ada akses diam-diam ke seluruh file.

PETUNJUK MELANJUTKAN PROYEK
- Sebelum mengedit, periksa git status, branch dan commit terkini; buat perubahan sekecil mungkin.
- Jangan menghapus/mengganti applicationId jika APK harus menjadi update terhadap aplikasi yang sudah terpasang.
- APK yang ditandatangani key berbeda tidak dapat memasang update di atas APK lama. Pertahankan secrets signing yang sudah dikonfigurasi; jangan membuat key pengganti.
- Jangan commit keystore, API keys, nilai secrets, data pengguna, atau file build.
- Jalankan ./gradlew testDebugUnitTest assembleDebug (workflow menguji test dan membuat artifact bertanda tangan stabil).
- Periksa laporan crash nyata sebelum menyimpulkan akar masalah. Laporan ada di dialog awal setelah force close atau halaman Crash Report.
- Untuk Backup Aman, gunakan MediaStore.Files pada Android 10+ untuk path “Relxio/Backup aman” dan SAF dengan persistable URI grant sebagai fallback bila perangkat menolak folder root maupun pada Android 8–9. Hindari izin storage luas.
- Bagian file aktual di akhir dokumen dihasilkan otomatis oleh Gradle pada build. Deskripsi arsitektur di template ini perlu ditinjau bila behavior utama berubah. Verifikasi commit dan isi file sebelum menjadikannya spesifikasi final.

CATATAN PRIVASI
Laporan crash memuat stack trace, model perangkat, versi Android, versi aplikasi, waktu, dan nama thread. Jangan menambahkan isi layar, clipboard, API key, password, atau rahasia ke laporan. File Backup Aman berupa teks plain; pengguna sebaiknya membagikannya hanya kepada pihak yang dipercaya.
